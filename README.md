# 狼人杀 · DSH Agent 预设

> 新建一个会话，选「狼人杀」—— 你面前的智能体就是**法官（上帝）**，
> 它用子代理扮演其他玩家，按顺序叫号，把每个人说了什么原样转述给你。

**整个游戏没有一个字节的 JS 代码。** 规则、流程、叫号、裁决、复盘，全部写在
`cordis.patch.yml` 里那段 **6.8 KB 的中文提示词**里。

---

## ⚠️ 开局前必做：把「工作步骤展示」设成『简洁』

**这一步不做，牌局会当场被剧透** —— 默认模式下每轮都会弹出「🤖 子任务状态更新」卡片，
展开就能看到各个 AI 玩家的**身份和私下消息**。

设成简洁后，每轮只留一行折叠条：

![已完成，用时 34 秒，右侧带展开箭头](docs/images/expand-steps.png)

**这一行恰恰是你要的东西：**

| 你做的事 | 结果 |
|---|---|
| **不展开**（默认） | 看不到任何身份与夜间动作 —— **不剧透** |
| **点右边的 ⌄ 展开** | 看到该玩家的**完整发言原文** —— **复盘不受影响** |

换句话说：**剧透权交回你自己手上**。想看就看，不想看就一直干干净净。

> 法官在开局时也会主动提醒你这件事，并告诉你展开的方法。

## 它是怎么工作的

### ① 身份靠「消息前缀」切换，而不是两套预设

DSH 的 `spawnTeammate` **不支持给子代理指定不同的预设** —— 子代理会**继承父级的 agent 预设**
（这条是从真实对局日志里实测确认的，见下文"实测数据"）。

所以玩家的系统提示词里，**和法官一字不差**，全都写着"你是全知全能的上帝"。

解法是把 persona 写成**双角色**：

```
◆ 消息以 [玩家N] 开头 → 你【只是 N 号玩家】，没有上帝视角
◆ 其余一切情况        → 你是【上帝（法官）】，全知全能
```

这样无论子代理是否继承 persona 都不会出事 —— **把未知量设计成不重要，比花时间去测量它更划算。**

### ② 法官是唯一的全知者，也是唯一的隔离点

| 角色 | 知道什么 |
|---|---|
| 法官 | 全部身份 + 全部夜间行动 |
| AI 玩家 | 只有法官在 `send_message` 里写给它的那一份 |
| 你 | 只有公开信息 + 你自己的身份 |

隔离不靠机制，靠**法官不把不该说的说出去** —— 全部约束都在提示词的第一节「上帝铁律」和第十节「输出纪律」里。

### ③ 玩家只回文本，不碰任何状态

AI 玩家没有任何游戏工具，只负责"说话 + 做决定"。所有状态都在法官的上下文和 `todo_write` 里。

## 安装

```bash
# 1. 克隆
git clone https://github.com/banana770/dsh-werewolf.git

# 2. 安装（用 DSH 的插件管理器，不要手动改 profile）
#    让 agent 执行：
#    plugin_manager { action: "install_bundle", target: "<克隆目录的绝对路径>" }
```

装完后**新建会话**，在预设里选「狼人杀」。

> 现有会话不会变 —— 预设在会话创建时就固定了。

## 卸载

```
plugin_manager { action: "remove_bundle", target: "@local/dsh-werewolf" }
```

只影响这一个预设，不动任何其它插件。

## 怎么玩

1. 新建会话 → 选「狼人杀」
2. 跟它说「开始」，或用弹出的选项选**板子**（6 / 9 / 12 人局）和**模式**（我参与 / 全 AI 观战）
3. **开局建议先玩 6 人局**（5 个 AI，稳）
4. 轮到你时会看到这样的播报：

```
📍 第 1 天 · 发言阶段（顺序：5→6→1→2→3→4）

5 号：「打头阵没信息，先表水：民牌一个。平安夜这板子没守卫，
      只有女巫解药能解释…」
6 号：「我 6 号，民牌一张，不怕查。目前全场只有 4 号一个跳预言家的…」
1 号：（跳过发言）

🎤 轮到你了（3 号）。请发言，或回复「跳过」。
```

## ⚠️ 界面上的泄漏出口（重要）

**你和法官同处一个会话，所以法官的"工作痕迹"你也看得见。**
提示词管得住"法官别在正文里说"，管不住界面本身。目前已知的出口：

| 出口 | 在哪看 | 剧本里的对策 | 你能做的 |
|---|---|---|---|
| 回复正文 | 对话流 | 第十节「输出纪律」+「问夜间行动时不许帮他分析」 | — |
| **玩家回给法官的消息** | **对话流（不折叠）** | 第十一节④：不许让玩家复述身份 | — |
| 子任务状态卡片 | 每轮的折叠条 | — | **设为「简洁」**（见开头） |
| `todo_write` 进度 | 会话里的待办列表 | 第十一节：只准写阶段，不准写身份 | — |
| 成员描述 | 页头「智能体团队」/ 右侧栏 | 第十一节：只准写「N 号座位玩家」 | 按 Esc 关掉面板 |
| 团队任务板 | 右侧栏任务管理 | 第十一节：干脆不用 | — |

> ⚠️ **第二个出口最隐蔽**：子代理每轮结束时，运行时会把它最后说的话作为一条消息塞进法官会话 ——
> **真人看得见，而且不折叠**。所以"让玩家复述身份确认"这种写法等于当众报牌。
> 剧本里已禁止，但你要知道这个通道存在。

> 这些出口**全部是被真实对局抓出来的**，不是推演出来的。
> 你如果发现新的显示渠道，按同样思路堵就行。

## 自定义

**`cordis.patch.yml` 里的 `persona.prefix` 就是整个游戏。** 改它 = 改游戏。

| 想改什么 | 改哪一节 |
|---|---|
| 主持流程、播报格式 | 第五、十节 |
| 板子与裁决规则 | 第二、七节 |
| 给 AI 玩家的话术模板 | 第六节 |
| 泄漏约束 | 第一、十一节 |

改完的完整动作：

```bash
# 1. 改 cordis.patch.yml
# 2. 校验（YAML 没写坏、剧本没被折叠、关键段落没丢）
node tools/yaml-check.mjs
# 3. 让预设重新加载（免重启）
#    plugin_manager set_bundle(false) → set_bundle(true)
# 4. 新建会话试玩
```

## 实测数据

这个预设是**靠两局真实对局的日志反推着改出来的**，不是一次写成的。
两份复盘（`docs/08`、`docs/09`）记录了每一次修复的证据。

最有价值的一次是 **9 人局**：它用的剧本恰好**带着部分加固、缺另一部分**，
构成了一次天然的对照实验，直接判定出：

| 发现 | 结论 |
|---|---|
| 子代理**确实继承**父级 agent 预设，且玩家与法官的 persona 一字不差 | 前缀切换规则不是过度设计，**是本设计成立的前提** |
| 「输出纪律」一条规则同时压住了夜间泄漏**和**教练式输出 | 后加的另一条禁令是冗余的 |
| `todo_write` 里赫然写着「狼队已定刀 5 号（3:0 一致）；预言家 3 号已查 7 号（金水）」 | 界面泄漏面比预想大得多 → 催生第十一节 |

## 支持更多人局：智能体上限怎么解决

12 人局需要 **11 个 AI 玩家**。默认配置下会卡住 —— 但卡住的
**不是子代理上限（`maxActiveSubagents`），是团队成员上限（`maxMembers`）**。

### 症结：`maxMembers` 被 profile 压到了 8

DSH 的 agent-team 服务有一个成员上限。**它的出厂默认其实是 16**，
但不少 profile（包括本机）在配置里把它显式压成了 **8**：

```yaml
# $DSH_HOME/profiles/<profile>/cordis.yml
- id: agent-team
  name: '@deepseek-ai/dsh-experimental-agent-team'
  config:
    maxMembers: 8        ← 就是这一行
    maxTasks: 256
```

创建第 9 个成员时会被直接拦下。

### 解决：改成 12，然后**重启 DSH**

```yaml
    maxMembers: 12       # 11 个 AI 玩家 + 你 = 12 席
```

改之前先备份（例如 `cordis.yml.bak-maxmembers`），想还原直接盖回去。

> ⚠️ **必须重启 DSH。热重载不生效。**
> 实测：改完配置后热重载 `agent-team` 插件，再创建第 9 个成员**依然被拦** ——
> loader 用的是装载时缓存的旧 config。重启后新上限才会读进去。

### 容量速查

| 板子 | 需要 AI 玩家 | `maxMembers: 16`（出厂默认） | 被压到 8 时 |
|---|---|---|---|
| 6 人局 | 5 | ✅ | ✅ |
| 9 人局 | 8 | ✅ | 🟡 刚好占满 |
| 12 人局 | 11 | ✅ | ❌ **需调高 + 重启** |

---

### 另一个坑：teammate 的模型在创建时就固定了

实战踩过一次：8 个 AI 玩家的回合**集体失败**，而法官一切正常。

原因：teammate 在**创建那一刻**就绑定了当时的默认模型，
而那个 provider 后来挂了 —— **成员建好之后改不动**。
法官换了模型也没用，因为玩家的模型是各自固定死的。

**兜底方案：改用子代理（subagent）顶替 teammate 当玩家。**

- 体验一致 —— 法官每次发话都会把完整局势带给他们
- 代价是每轮要重发上下文（子代理不像 teammate 那样常驻记忆）
- 创建时可以用 `agentOptions` 指定模型，不受成员绑定限制

这也是本预设**同时挂载 `tool-subagent`** 的原因 —— 它不只是备用，
teammate 集体失灵时它就是主路径。

## 已知限制

| # | 限制 |
|---|---|
| 1 | **法官是 LLM，不是引擎。** 规则靠它自觉，长局理论上可能漏步或算错票 |
| 2 | 玩家会继承法官 persona（靠前缀规则化解，非机制保证） |
| 3 | 12 人局需把 `maxMembers` 调到 ≥12 **并重启 DSH**（见上一节） |
| 4 | teammate 的模型在创建时固定，provider 挂了就集体失灵（可改用子代理） |
| 5 | 每个玩家每轮都要背着完整的 9.6 KB 剧本，token 成本偏高 |
| 6 | 战绩不落盘，全在会话上下文里 |
