# 测试与验收

> 狼人杀插件最容易"看起来能跑，其实是假的"。本文档定义**怎么证明它是对的**。
> 核心策略：**把不确定性关在笼子里** —— 引擎 100% 确定性、可单测；只有"发言质量"允许模糊。

---

## 1. 测试分层

| 层 | 对象 | 依赖 | 速度 | 何时跑 |
|---|---|---|---|---|
| **L0** | 引擎纯函数 | 无 | 毫秒 | 每次改动 |
| **L1** | 剧本回放 | 无 | 毫秒 | 每次改动 |
| **L2** | 模糊测试（随机 bot） | 无 | 秒 | 提交前 / CI |
| **L3** | 信息隔离断言 | 无 | 秒 | 提交前 |
| **L4** | 端到端（真 LLM） | 模型 | 分钟 | 里程碑 |
| **L5** | 人工验收 | 你 | 分钟 | 里程碑 |

**L0–L3 全部不需要 LLM**，所以可以高频跑。这是本方案最重要的工程决定。

### 2.2 流程正确性

| 组 | 用例 |
|---|---|
| 阶段推进 | `advance()` 严格按 `03` 第 4 节的状态图；不落步、不跳步 |
| 顺序校验 | 用过期 `expectedStep` 调 `act()` → `STALE_STEP` |
| 幂等 | 同一动作提交两次 → 第二次被拒且状态不变 |
| 死亡发言 | 死者 `day.speech` / `day.vote` → `DEAD` |
| 白痴票权 | 翻牌后投票 → `NOT_PENDING` |
| 平票链 | 平票 → PK → 再平票 → 无人出局 |
| 警长平票 | 平票 → PK → 再平票 → `badge='lost'` |
| 自爆 | 白天自爆 → 立即 `night.guard`，`day` +1，无遗言 |
| 开枪链 | 猎人 A 打死猎人 B，B 再开枪 → 链式，且每人只开一次 |
| 终结 | 神灭 / 民灭 / 屠城 三种胜负各自的终局 |
| 同时满足 | 最后一狼与最后好人同归于尽 → **好人胜** |
| 遗言 | 四种死法 × 遗言资格矩阵 |
| 序列化 | `GameState` JSON 往返后 `deepEqual` |

## 4. L2 · 模糊测试（最有价值的一层）

```
跑 1000 局：随机 bot 代替 AI 玩家（合法动作里随机选，含弃权）
```

**必须全绿的不变量**：

| # | 不变量 |
|---|---|
| F1 | 每局**必然终止**（不超 100 天 / 不死循环） |
| F2 | 存活人数**单调不增** |
| F3 | 狼人数**单调不增** |
| F4 | 事件流与状态**始终一致**（回放事件流可重建状态） |
| F5 | 任意时刻 `view(s, seat)` 不含该座位不该有的字段（抽样 + 逐座位） |
| F6 | 无 `EngineError` 逃逸到顶层（合法动作集永不产生非法动作） |
| F7 | 每局的 `winner` 必为 `'good' | 'wolf'`（无平局悬空） |
| F8 | 座位数、角色数守恒 |

**F6 是关键**：如果"随机选合法动作"还能触发 `EngineError`，说明 `legal()` 与 `act()` 不一致 —— 这是引擎最典型的 bug。

## 5. L3 · 信息隔离断言

见 `04-玩家与AI设计.md` 第 8 节（C1–C5）。这里补**实现方式**：

```ts
// 伪代码：C1 的精确实现（不用关键词匹配，用座位-角色映射）
for (const seat of seats) {
  const prompt = buildPlayerPrompt(state, seat)   // 玩家实际收到的完整文本
  const others = seats.filter(s => s.id !== seat.id)
  for (const o of others) {
    const roleName = ROLE_DISPLAY[o.role]          // "预言家" / "狼人" …
    // 只有在允许的场景才可出现：狼队友互认、公开跳身份
    if (!allowedByView(state, seat, o)) {
      expect(prompt).not.toContain(`${o.id}号是${roleName}`)
    }
  }
}
```

**误伤处理**：公开发言里玩家自称身份（"我是预言家"）是**合法**的，断言只检查**引擎注入的私有情报段**，不检查玩家自己的发言正文。
