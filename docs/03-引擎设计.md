# 引擎设计（`src/engine/`）

> 引擎是**唯一真相源**。它不知道 LLM 存在，不认识 DSH，只是纯函数式的状态机。
> 这条不变量换来两件事：可以被单测压死、可以被 1000 局模糊测试跑穿。

---

## 1. 设计不变量（硬约束）

| # | 不变量 | 违反后果 |
|---|---|---|
| I1 | `engine/` **不得** import 任何 DSH / LLM / 网络 / 文件系统模块 | 无法纯单测、模糊测试 |
| I2 | 所有状态变更必须经过 `act()` / `advance()`，不得外部直接改 `GameState` | 状态可被绕过，隔离失效 |
| I3 | **`view(state, seat)` 是玩家可见信息的唯一出口** | 一处绕过 = 全局泄漏 |
| I4 | 引擎是**确定性**的：相同 seed + 相同动作序列 → 相同结果 | 无法复盘、无法调试 |
| I5 | 引擎不产生自然语言；文案由 `narration` 层按模板生成 | 文案泄漏信息 |

## 3. 核心数据结构

```ts
// ---------- 角色 ----------
export type RoleId =
  | 'wolf' | 'wolfking' | 'whitewolfking'
  | 'guard' | 'seer' | 'witch' | 'hunter' | 'idiot'
  | 'villager'

export type Camp = 'wolf' | 'good'

export interface RoleDef {
  id: RoleId
  name: string                 // 狼人 / 预言家 …
  camp: Camp
  nightOrder: number | null    // 1=守卫 2=狼 3=女巫 4=预言家 5=猎人 6=白痴；null=不睁眼
  actsAtNight: boolean
  desc: string
}

// ---------- 板子 ----------
export interface Board {
  id: string
  name: string
  players: number
  roles: RoleId[]              // length === players
  rules?: Partial<RuleFlags>
}

// ---------- 规则开关（裁决矩阵的代码形态）----------
export interface RuleFlags {
  witchSelfHealFirstNight: boolean   // R1  默认 true
  witchDoublePotionForbidden: boolean// R2  默认 true
  poisonedCannotShoot: boolean       // R3  默认 true
  guardCanSelfGuard: boolean         // R4  默认 true
  sameGuardHealDies: boolean         // R5  默认 true
  lastWordsFirstNightOnly: boolean   // R6  默认 true
  sheriffVoteWeight: number          // R7  默认 1.5
  explodeCanTransferBadge: boolean   // R8  默认 true
  wolfDisagreePolicy: 'majority-earliest' | 'random' | 'first'  // R9
  wolfEmptyKillNeedsAll: boolean     // R10 默认 true
}

// ---------- 座位 ----------
export interface Seat {
  id: number                   // 1..N
  role: RoleId
  alive: boolean
  canVote: boolean             // 白痴翻牌后 false
  revealedIdiot: boolean
  hasGun: boolean              // 猎人/狼王尚可开枪
  deathCause?: 'wolf' | 'poison' | 'vote' | 'gun' | 'explode'
  deathDay?: number
  deathAt?: 'night' | 'day'
}

// ---------- 阶段 ----------
export type Phase =
  | 'setup'
  // 夜晚
  | 'night.guard' | 'night.wolves' | 'night.witch' | 'night.seer'
  | 'night.hunter' | 'night.idiot' | 'night.resolve'
  // 白天
  | 'day.announce'
  | 'day.sheriff_signup' | 'day.sheriff_speech' | 'day.sheriff_vote' | 'day.sheriff_pk'
  | 'day.lastwords'
  | 'day.speech'
  | 'day.vote' | 'day.vote_pk'
  | 'day.exile' | 'day.shoot' | 'day.explode_window'
  | 'ended'

// ---------- 游戏状态（引擎的唯一真相）----------
export interface GameState {
  id: string
  seed: number
  board: Board
  mode: 'M1' | 'M2' | 'M3'
  humanSeat: number | null     // M1 用
  day: number                  // 0 = 首夜
  phase: Phase
  step: number                 // 单调递增：幂等 + 顺序校验
  seats: Seat[]
  sheriff: number | null
  badge: 'held' | 'lost' | 'transferred'
  witch: { heal: number; poison: number }
  guardLast: number | null     // 用于"不能连守"
  night: NightActions
  day_?: DayActions
  votes: VoteRound[]
  events: GameEvent[]
  winner: Camp | null
  pending: PendingAction[]     // 当前阶段等谁交什么
}

export interface NightActions {
  guard?: number | null
  wolfKills: { seat: number; target: number | null }[]   // 每狼独立提交
  witchHeal?: boolean
  witchPoison?: number | null
  seerCheck?: number
  seerResults: { day: number; target: number; camp: Camp }[]
}

export interface PendingAction {
  seat: number | 'all' | 'sheriff'
  kind: 'guard' | 'kill' | 'heal' | 'poison' | 'check'
      | 'signup' | 'speech' | 'sheriffVote' | 'vote' | 'shoot' | 'explode' | 'badge'
  deadlineStep: number         // 超时兜底用
}
```

## 4. 阶段状态机

```
setup
  └─→ night.guard → night.wolves → night.witch → night.seer
        → night.hunter → night.idiot → night.resolve
              └─→ day.announce
                    ├─(day===1)→ day.sheriff_signup → day.sheriff_speech
                    │             → day.sheriff_vote → [day.sheriff_pk] → day.lastwords
                    └─(day>1)──→ day.lastwords
                                      └─→ day.speech → day.explode_window?
                                            → day.vote → [day.vote_pk] → day.exile
                                                  → day.shoot? → day.lastwords?
                                                        └─→ (胜负判定)
                                                              ├─ 结束 → ended
                                                              └─ day++ → night.guard
```

**`advance()` 语义**：从当前阶段推进到**下一个需要外部输入的阶段**，自动跳过无条件阶段（如 `night.resolve`、`day.announce` 直接算出结果）。

**`step` 单调递增**：每次 `act`/`advance` 都 +1。所有动作带 `expectedStep`，不匹配则拒绝 —— 这是**幂等与防乱序**的关键。

## 5. 夜晚结算算法（`night.ts` + `resolve.ts`）

严格实现 `01-规则手册.md` 第 4.1 节，逐行对应：

```ts
export function resolveNight(state: GameState): DeathRecord[] {
  const r = state.board.rules!
  const { guard, wolfKills, witchHeal, witchPoison } = state.night
  const deaths: DeathRecord[] = []

  // 1. 狼刀目标（R9 聚合策略）
  const voteCount = countTargets(wolfKills)
  const killTarget = aggregateWolfTarget(voteCount, wolfKills, r.wolfDisagreePolicy)

  if (killTarget != null) {
    const guarded = guard === killTarget
    const healed = witchHeal === true
    // R5：同守同救必死
    const dies = r.sameGuardHealDies
      ? !guarded || healed          // 守+救 → 死；仅守 → 活；仅救 → 活；都没有 → 死
      : !(guarded || healed)
    if (guard === killTarget && healed) {
      deaths.push({ seat: killTarget, cause: 'wolf', note: 'same-guard-heal' })  // R5=true
    } else if (dies) {
      deaths.push({ seat: killTarget, cause: 'wolf' })
    }
  }

  // 2. 毒药（无视守卫）
  if (witchPoison != null) deaths.push({ seat: witchPoison, cause: 'poison' })

  // 3. 去重 + 死因优先级（毒 > 刀，用于 R3 开枪判定）
  return dedupeByPriority(deaths)   // 若同一人被刀且被毒 → cause='poison'
}
```

> ⚠️ 上面 `dies` 的布尔表达式必须与 R5 单测逐格对齐（4 种组合 × R5 两种取值 = 8 个断言）。

**开枪链处理**（`resolve.ts`）：死亡结算后，若死者是猎人/狼王 且 `hasGun` 且 `cause !== 'poison'`（R3），插入 `day.shoot` 阶段请求开枪目标；开枪致死的人若也是猎人则**继续链式**（防无限递归：最多 N 次，且每人只开一次）。

## 6. 白天流程要点

| 阶段 | 关键逻辑 |
|---|---|
| `sheriff_signup` | 收集报名；无人报名 → 无警长 |
| `sheriff_speech` | 按报名顺序；每人可发言或退水；退水者不进入投票候选 |
| `sheriff_vote` | **仅未上警的存活玩家**投票；权重 1；平票 → `sheriff_pk` |
| `sheriff_pk` | 平票者发言 → 重投；再平票 → `badge='lost'`（无警长） |
| `day.speech` | 顺序由警长定；无警长默认死左；每限时 |
| `day.explode_window` | 狼人可自爆 → 立即跳 `night.guard`，`day++`，无遗言；R8 决定能否移交警徽 |
| `day.vote` | 存活且 `canVote` 的玩家投票；警长权重 `sheriffVoteWeight` |
| `day.vote_pk` | 平票者 PK → 重投；再平票 → 无人出局 |
| `day.exile` | 白痴 → 翻牌免死，`canVote=false`，不入夜 |
| `day.shoot` | 被放逐的猎人/狼王开枪 |

**计票函数**（唯一实现，全部投票复用）：

```ts
function tally(votes: Vote[], sheriff: number | null, weight: number): Map<number, number>
// 弃票 = 不投 → 不计入任何目标
```

## 7. ★ 可见性矩阵（信息隔离唯一依据）

`view(state, seat)` 输出该座位**能**看到的字段。下表逐格定义。

| 信息 | 自己 | 狼队友 | 其他好人 | 死人 | 上帝/观众(M2) |
|---|---|---|---|---|---|
| 自己的身份 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 狼队友身份 | — | ✅ | ⛔ | ⛔ | ✅ |
| 座位存活状态 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 每日死讯（谁倒牌） | ✅ | ✅ | ✅ | ✅ | ✅ |
| **死因**（刀/毒） | ⛔ | ⛔ | ⛔ | ⛔ | ✅ |
| 公开发言记录 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 投票票型（公开后） | ✅ | ✅ | ✅ | ✅ | ✅ |
| 警长归属 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 刀人目标 | 仅当自己是狼 | 仅当自己是狼 | ⛔ | ⛔ | ✅ |
| 女巫用药 | 仅当自己是女巫 | ⛔ | ⛔ | ⛔ | ✅ |
| 守卫守护 | 仅当自己是守卫 | ⛔ | ⛔ | ⛔ | ✅ |
| 预言家查验结果 | 仅当自己是预言家 | ⛔ | ⛔ | ⛔ | ✅ |
| 猎人/狼王开枪状态 | 仅当自己是该角色 | ⛔ | ⛔ | ⛔ | ✅ |
| 剩余牌库 / 板子构成 | ✅（公开） | ✅ | ✅ | ✅ | ✅ |

**死人不发声**：死者 `view` 仍然可读（用于复盘的"上帝视角回放"），但引擎拒绝其在 `day.speech` / `day.vote` 的 `act`。

**实现要求**：`view.ts` 必须**白名单式**构造返回值（新建对象、逐字段赋值），**禁止**用 `{...state}` 或 `JSON.parse(JSON.stringify(state))` 再删字段 —— 后者一旦漏删就是致命泄漏。

## 8. 事件流（`events.ts`）

```ts
export type GameEvent =
  | { t: 'game.start';  day: 0; board: string; mode: string; seed: number }
  | { t: 'deal';        assignments: Record<number, RoleId> }        // 仅存日志，不进任何人 view
  | { t: 'night.act';   day: number; seat: number; kind: string; target: number | null }
  | { t: 'night.deaths';day: number; seats: number[]; causes: string[] }
  | { t: 'day.announce';day: number; text: string }
  | { t: 'sheriff';     day: number; elected: number | null; votes: VoteRound }
  | { t: 'speech';      day: number; seat: number; text: string; len: number }
  | { t: 'vote';        day: number; round: number; ballots: Ballot[]; tally: Record<number, number> }
  | { t: 'exile';       day: number; seat: number | null; reason: 'vote' | 'pk-tie' }
  | { t: 'explode';     day: number; seat: number }
  | { t: 'shoot';       day: number; seat: number; target: number; hit: boolean }
  | { t: 'idiot.flip';  day: number; seat: number }
  | { t: 'game.end';    winner: 'good' | 'wolf'; reveal: Record<number, RoleId> }
```

**两个消费方**：
1. `narration.ts` → 生成玩家可见公告（**过滤死因/夜间细节**）
2. 战报导出 → 生成 markdown / 完整上帝视角 json

## 9. 公开 API（`engine/index.ts`）

```ts
export function createGame(opts: {
  board: Board | string        // id 或对象
  mode: 'M1' | 'M2' | 'M3'
  humanSeat?: number | null
  seed?: number                // 不传则随机并记录
  rules?: Partial<RuleFlags>   // 覆盖板子默认
}): GameState

export function view(s: GameState, as: number | 'god'): PlayerView
export function pending(s: GameState): PendingAction[]
export function legal(s: GameState, seat: number): ActionKind[]
export function act(s: GameState, a: Action): ActionResult   // 含 expectedStep 校验
export function advance(s: GameState): GameState             // 推进到下一个输入点
export function isOver(s: GameState): boolean
export function replay(seed: number, actions: Action[]): GameState
export function exportReport(s: GameState, style: 'god' | 'player', seat?: number): string
```

**`act()` 的校验顺序**（任一失败即抛 `EngineError`，且**不改状态**）：

1. `step` 匹配？
2. 该阶段是否等待这个座位？（`pending` 里有它吗）
3. 该座位是否存活 / `canVote`？
4. 动作 kind 是否是该角色在该阶段**合法**的动作？
5. 目标是否存活、是否合法（如守卫不能连守、女巫不能双药、解药不能救自己〔非首夜〕）？
6. 写入 `night.*` / `day_*`，`step++`，追加事件。

## 11. 错误与非法动作

```ts
export class EngineError extends Error {
  code: 'STALE_STEP' | 'NOT_PENDING' | 'DEAD' | 'ILLEGAL_ACTION'
      | 'ILLEGAL_TARGET' | 'RULE_VIOLATION' | 'GAME_OVER'
  detail: string
}
```

**超时兜底**（由上层驱动层调用，引擎提供 `defaultAction(state, pending)`）：

| 阶段 | 默认动作 |
|---|---|
| 夜晚任意角色 | 弃权（守卫不守 / 狼空刀 / 女巫不用药 / 预言家不验） |
| 发言 | 记录空发言 `"(弃权发言)"` |
| 投票 | 弃票 |
| 开枪 | 不开枪（视为放弃） |
| 警长竞选 | 不上警 |
