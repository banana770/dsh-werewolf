# 玩家与 AI 设计（`src/host/players/`）

> 这一层负责把"引擎里的一个座位"变成"一个真的会思考的 AI 玩家"，同时**不让它知道不该知道的事**。

---

## 1. 三种驱动路线（已实测源码后定案）

| 路线 | 机制 | 上下文隔离 | Token 成本 | 依赖 | 结论 |
|---|---|---|---|---|---|
| **A · 会话侧驱动** | 法官（Lead 会话）用**现成**的 `spawn_teammate` / `subagent` / `send_message` 驱动玩家 | 强（每人独立上下文） | 中 | **零新 API** | ✅ **首选，先做** |
| **B · 服务侧驱动** | 插件调 `ctx.get('subagents')` 的 start/continue API | 强 | 低（常驻复用） | 需锁定服务签名 | ⏳ 二期优化 |
| **C · 混合** | 引擎自动推进 + A/B 可切换 | 强 | 低 | 两者 | 🎯 终态 |

**为什么 A 是首选**：我实测确认 `@deepseek-ai/dsh-subagent` 是一个"服务 + 提供方 + 工具"的 seam，**面向模型的委派工具已存在且可用**（我当前就有 `spawn_teammate` / `subagent` / `send_message`）。先用现成工具把玩法跑通，再决定要不要下沉到 B。

### 1.1 关键设计决定：玩家**不需要**任何工具

| 方案 | 玩家如何提交动作 | 评价 |
|---|---|---|
| ❌ 给玩家装引擎工具 | 玩家自己调 `wolf_act` | 玩家能碰引擎状态，隔离面变大 |
| ✅ **玩家只回文本** | 玩家回复里带结构化决策块，**法官解析并代调** `wolf_act` | 玩家永远碰不到引擎；隔离最干净 |

**采用后者。** 玩家是纯"思考+说话"的代理，法官是唯一能碰引擎的角色。

## 2. 玩家上下文构造

每个 AI 玩家的上下文**只**由下列内容组成，逐项都可审计：

```
┌─ system / persona ────────────────────────────────┐
│ 1. 角色提示词（见第 5 节，按身份选一套）              │
│ 2. 规则摘要（板子 + 裁决矩阵关键项，见 01 手册）        │
│ 3. 本局元信息：板子名、人数、你的座位号、你的身份        │
│ 4. 输出格式契约：如何写决策块、发言长度上限            │
└───────────────────────────────────────────────────┘
┌─ 每轮 user 消息 ──────────────────────────────────┐
│ 5. 【私有信息】引擎 view(state, mySeat) 的私密部分     │
│    · 狼队友是谁 / 我的查验结果 / 我的用药与守护记录      │
│ 6. 【公开信息】存活名单、每日死讯、全部公开发言、历轮票型  │
│ 7. 【本轮任务】现在轮到你做 X（选择刀人目标 / 发言 / 投票）│
└───────────────────────────────────────────────────┘
```

**硬性约束**：第 5、6 项必须**逐字段来自 `engine.view(state, seat)`**。不得由法官"顺手补充"任何信息 —— 那是泄漏的唯一现实来源。

## 3. 记忆模型

```ts
interface PlayerContext {
  seat: number
  role: RoleId
  camp: Camp
  facts: PlayerFact[]        // 只装该玩家该知道的（来自 view）
  publicLog: SpeechRecord[]  // 公开发言
  privateLog: PrivateNote[]  // 私有情报（查验/用药）
  round: number
}

// 由 engine.view() 直接产出，禁止手工拼装
interface PlayerFact {
  kind: 'identity' | 'teammate' | 'check' | 'potion' | 'guard'
      | 'death' | 'vote' | 'sheriff' | 'speech'
  day: number
  payload: unknown
}
```

### 3.1 长局上下文压缩

12 人局可能打到 5–6 天，公开发言会很长。策略：

| 保留 | 压缩 |
|---|---|
| 本人的全部私有情报 | 早期的公开发言 → 摘要（谁站边谁、谁被查杀） |
| 最近 2 天的完整发言 | 更早的 → 每人数十字要点 |
| 全部票型（结构化，很省） | — |
| 死亡名单与顺序 | — |

**压缩必须由引擎侧的确定性规则生成**（按事件流做摘要），不能交给 LLM 自由发挥 —— 否则摘要本身会变成泄漏通道或失真源。

## 4. 决策协议（结构化）

玩家每轮回复必须是"**发言 + 决策块**"：

````
我觉得 5 号昨天的发言有问题，他站边太急，而且警徽流报得像是背过的。
我倾向投 5 号。

```wolf
{"action":"vote","target":5,"reason":"站边异常，警徽流可疑"}
```
````

**解析规则**（法官侧，容错优先）：

| 情况 | 处理 |
|---|---|
| 有合法 ```wolf 块 | 采用 |
| 无代码块但文末有明确动作 | 用一次 LLM 抽取降级解析 |
| 完全解析不出 | **超时兜底动作**（弃票/空刀），并记 `parse_fail` 事件 |
| target 不合法（已死/自己/不存在） | 引擎拒绝 → 让该玩家**重试一次** → 再失败则兜底 |

**各阶段的决策 schema**：

| 阶段 | 决策块 |
|---|---|
| 守卫 | `{"action":"guard","target":3}` / `{"action":"guard","target":null}` |
| 狼人 | `{"action":"kill","target":7}` / `{"action":"kill","target":null}` |
| 女巫 | `{"action":"heal","use":true}` + `{"action":"poison","target":null}` |
| 预言家 | `{"action":"check","target":5}` |
| 上警 | `{"action":"signup","join":true}` |
| 警长投票 | `{"action":"sheriffVote","target":2}` / `{"action":"abstain"}` |
| 发言 | `{"action":"speak"}`（正文即发言） |
| 放逐投票 | `{"action":"vote","target":5}` / `{"action":"abstain"}` |
| 开枪 | `{"action":"shoot","target":9}` / `{"action":"shoot","target":null}` |
| 自爆 | `{"action":"explode"}` / 不出现此块即不自爆 |
| 移交警徽 | `{"action":"badge","target":4}` / `{"action":"badge","target":null}`（撕） |

## 5. 角色提示词模板（`src/host/prompts/`）

六套模板，每套三部分：**你是谁 / 你知道什么 / 你怎么赢**。

### 5.1 通用骨架

```
你是狼人杀玩家 {seat} 号。本局板子：{board}，共 {n} 人。
你的身份是【{roleName}】，你属于{campName}阵营。

【胜利条件】{winCondition}

【你的技能】{skillDesc}

【发言要求】
- 用中文，{maxLen} 字以内，口语化，像真人面杀发言。
- 必须使用狼人杀术语（金水/查杀/悍跳/警徽流/站边…）。
- 不要暴露你不是人类的任何迹象。
- 发言要有信息量：表态、给理由、给投票意向。

【决策要求】
- 在回复末尾输出一个 ```wolf 代码块，内容为 JSON。
- 本轮你要做的是：{pendingKind}，合法动作：{legalActions}
```

### 5.2 各角色的"怎么赢"要点

| 角色 | 策略指引（写进提示词） |
|---|---|
| **预言家** | 尽量第一天报查验；给出**警徽流**（验人顺序 + 警徽移交）；被悍跳时要冷静对线，强调验人逻辑 |
| **女巫** | 前期藏身份；解药优先救关键神职或自救；毒药留给确定的狼；报药时机的把握 |
| **猎人** | 通常藏身份；被推出局时开枪要打"最像狼的"；可以适当跳身份施压 |
| **白痴** | 可适当激进发言吸收火力；翻牌后无票权，要用发言影响力带队 |
| **守卫** | 藏身份；守人要有逻辑（守预言家/守自己/守警长）；注意不能连守 |
| **平民** | 靠发言与投票立功；认真分析对跳、票型；不要划水，也不要乱跳身份 |
| **狼人** | 白天要伪装：可以悍跳预言家，可以倒钩站边真预言家；夜里统一刀人目标；注意队友身份与发言一致性 |

### 5.3 狼人队的**夜间沟通**

狼人是唯一需要"内部协商"的阵营：

```
第 1 轮：法官分别问每只狼"你想刀谁"（互不知情）→ 聚合（R9 多数决）
第 2 轮（可选，仅当有分歧）：把分歧结果告知狼队，让他们再议一次
```

默认**只做第 1 轮**（成本低）；`wolfDisagreePolicy` 决定聚合方式。

## 6. 容量、成本与降级

### 6.1 硬约束（实测源码）

| 约束 | 值 | 来源 |
|---|---|---|
| 常驻可续接子代理上限 | **默认 8**（`maxActiveSubagents`，可调为正安全整数） | `@deepseek-ai/dsh-subagent` |
| **一次性**子代理 | **不受此上限约束** | 同上 |
| 子代理深度 | `maxDepth` 默认 1 | 同上 |

### 6.2 按板子选择驱动方式

| 板子 | AI 玩家数 | 驱动方式 | 理由 |
|---|---|---|---|
| novice-6 | 5–6 | 常驻 teammate | ≤ 8，够用 |
| standard-9 | 8–9 | 常驻 teammate（M1 为 8，刚好）/ 一次性 | 临界，可调 |
| classic-12 | 11–12 | **一次性 subagent 轮询**（或调高 `maxActiveSubagents`） | 超默认上限 |

**降级链**：常驻 teammate → 调高上限 → 一次性 subagent（每轮打包记忆重放）→ 减少 AI 玩家数（不支持，会破坏板子）。

### 6.3 Token 预算粗估（standard-9，一局 ~3 天）

| 项 | 次数 | 说明 |
|---|---|---|
| 夜间决策 | 3 夜 × 3–4 角色 | 短提示词，输出短 |
| 公开发言 | 3 天 × 9 人 | **主要成本**（每人 200 字） |
| 投票 | 3 天 × 9 人 | 短 |
| 法官编排 | ~30 次工具调用 | 轻 |

**优化手段**：常驻上下文复用（KV cache 友好）、发言长度上限、早期发言摘要压缩。

## 7. 异常与兜底

| 异常 | 处理 |
|---|---|
| 玩家超时未回 | 用 `defaultAction()` 兜底，记事件，继续 |
| 玩家输出无法解析 | 降级解析 → 仍失败 → 兜底动作 |
| 玩家输出违规目标 | 引擎拒绝 → 重试 1 次 → 兜底 |
| 玩家"出戏"（说自己是 AI / 拒绝玩） | 记事件；法官提示一次；再犯则该座位改为规则 bot |
| 玩家上下文超限 | 触发记忆压缩（第 3.1 节） |
| 玩家中途死亡 | 停止唤醒；其上下文保留到复盘 |
| 法官（Lead）自己崩 | 引擎状态已持久化，可从 `replay.json` 恢复 |

## 8. ★ 信息隔离的验证方法（T4.3 的验收手段）

不能只靠"我觉得没泄漏"，必须有**自动化断言**：

| 检查 | 方法 | 通过标准 |
|---|---|---|
| C1 上下文无他人身份 | 对每个玩家的完整 prompt 文本，grep 其他座位的角色名 | **0 命中** |
| C2 无夜间私有信息泄漏 | grep `刀`/`毒`/`守`/`验` 相关字段是否出现在非本人视角 | 0 命中 |
| C3 死因不泄漏 | 检查所有发给玩家的文案不含"被刀/被毒" | 0 命中 |
| C4 上帝视角不外泄 | M1 模式下检查播报函数未被调用 | 静态断言 + 运行时断言 |
| C5 引擎侧可审计 | `view()` 单测：逐角色 × 逐字段断言白名单 | 全绿 |

**C1 的陷阱**：模糊匹配会误伤（如"狼人杀"含"狼"）。所以断言必须用**精确的座位-角色映射**，而不是关键词。

**M2 反向断言**：M2 模式下上帝视角**必须**输出 —— 防止修 bug 时把播报一刀切掉。
