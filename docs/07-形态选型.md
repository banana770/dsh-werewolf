# 形态选型：预设 / 独立网页 / 混合

> 本文回答两个连在一起的问题：
> ① 预设的形式会不会成为累赘？ ② 做成单独网页会不会更好？
>
> **结论先说**：① 会 —— 但只在把预设当"游戏载体"时；② 网页在 **UI/房间**这一层明显更好，在 **AI 大脑**这一层更弱。两者不是对立面，**正确的形态是分层**。

---

## 1. 预设会不会成为累赘

### 1.1 会 —— 当把它当成"游戏载体"时

| # | 累赘点 | 具体表现 |
|---|---|---|
| **B1** | **预设是 per-session 的，狼人杀是 per-player 的** | 一个预设描述**一个会话**的组合。而信息隔离要求**每个玩家一个独立上下文**。预设这一层**根本无法表达"N 个玩家"** —— 这是最根本的错配 |
| **B2** | **玩家会话继承什么组合，官方文档没写** | 我查了 `dsh-experimental-agent-team` 与 `dsh-experimental-tool-agent-team` 的 README 与实现：只说明"每个团队成员都会获得相同的九个 Team 工具"，**没有说明 teammate 继承哪个 agent 预设**。`dsh-subagent` README 只有一句措辞含糊的 *"父级让子级获得相同的 `permission/preset` 身份"*（很可能指**权限预设**而非 agent 预设）。→ **若玩家继承了法官预设，玩家就会拿到 `wolf_view`，直接开天眼**。这是个未验证的致命面 |
| **B3** | **预设是静态的，游戏是动态的** | 预设是"建会话时固定"的组合，运行中不可变。而一局游戏要经历 选模式 → 选板子 → 发牌 → 多阶段循环。这些**动态状态**必须活在引擎里，预设帮不上忙 |
| **B4** | **改一次要重装 + 重启 + 审批** | 预设 = bundle patch 声明行；替换已安装包需重启才加载新 JS 代际；`install_bundle` 在 Host 进程执行代码需 Full access 或审批。**游戏逻辑迭代频繁，这个摩擦是真实的** |

### 1.2 不会 —— 当它只承担"入口"时

预设真正擅长且不可替代的只有三件事：

1. **身份**：进去就是法官（persona 遮蔽部署级人设）
2. **工具面**：`wolf_*` 只对这个会话可见，不污染编码会话
3. **仪式感**：新建会话选「狼人杀」= 一个干净的入口

**只要预设不再承担"游戏本身"，它就不累赘。**

### 1.3 反向补充：预设也没那么糟

- 工具面裁剪 + persona 遮蔽确实是 DSH 提供的**正确机制**，没有更轻的等价物
- 开发期完全可以用 `dev_inject_plugin` / `dev_reload_package` 热迭代，绕开重装摩擦
- 它的问题**只在被要求承担它表达不了的东西时**才出现

## 2. 做成单独网页：强论据与弱论据

### 2.1 网页在这一层明显更好：**UI / 房间**

| # | 理由 |
|---|---|
| **W1** | **狼人杀是有界面的游戏**。聊天流表达不了：座位环形图、存活状态、私密身份牌、夜间操作面板、**票型表**（一眼看出抱团）、时间轴、发言计时器。我在 `02` 里给 M1 的真人交互只能靠 `ask_user_question`，体验差一截 |
| **W2** | **多真人联机免费得到**。网页开多个标签页 = 多个玩家。而 DSH 原生做 M4 要跨会话共享房间 + 身份认证 + 防偷看 —— 我上一版**直接把它砍了** |
| **W3** | **分发成本**。给别人玩：发个网址。DSH 预设：对方要装插件、装 bundle、过审批、重启 |
| **W4** | **绕开 B1–B4 全部四个累赘点** |
| **W5** | **你已经有 198 KB 的完整 UI**（`werewolfUI.html`），沉没成本已付 |

### 2.2 网页在这一层更弱：**AI 大脑**

| # | 理由 |
|---|---|
| **L1** | 要自己管：API key、并发、重试、超时、成本计量、上下文压缩 |
| **L2** | 要自己写角色 agent 框架与提示词工程 —— 而 persona / 工具 / 会话 / 记忆 / 多模型路由 **DSH 已经给了** |
| **L3** | 与 DSH 生态脱节：战报进不了会话、用不上记忆插件与技能、没法复用 DSH 的模型选择 |

### 2.3 关键事实：**你现在就是"网页 + 外部大脑"**

存量那套 = `werewolfUI.html`（网页 UI）+ `werewolf_server.py`（引擎/服务）+ OpenViking/VikingBot（大脑，7 个 channel）。

**所以真正的问题不是「网页 vs 预设」，而是「大脑用谁」。**

## 3. 网页可以挂进 DSH —— 两者不是对立面

本机实测可用的能力：

| 能力 | 状态 |
|---|---|
| `@deepseek-ai/dsh-host-webserver`（插件可注册 HTTP 路由） | ✅ active |
| `sidebar_open` 工具（把**本地 URL / 文件**开进侧边栏浏览器） | ✅ 本会话可用 |
| `ui-sidebar-browser` | ⚠️ 已安装但 **disabled**（需在设置里开启） |
| `web-ui-remote-web-ui` / `better-sidebar` | ✅ active |

→ **"独立网页"和"DSH 原生"可以同时成立**：网页是 UI 层，DSH 是驱动层。

---

## 4. 正确的分层

```
① 引擎层（纯逻辑）        语言无关、可单测、可模糊测试
   · 存量的 werewolf_server.py 里的规则逻辑  ≈  我 03 文档里的 TS 引擎
   · 二选一或先留 Python、后迁 TS

② 房间 / UI 层（网页）    ★ 网页在这里，明显更优
   · 座位图 / 身份牌 / 夜昼时间轴 / 票型表 / 发言流
   · WebSocket 或 SSE：公开频道广播，私密频道只推给对应座位
   · 多个浏览器标签 = 多个真人玩家（M4 免费获得）

③ 大脑层（可插拔）        ★ 这一层才需要选
   A) DSH agent（teammate / subagent）—— 模型好、生态全
   B) OpenViking / VikingBot —— 你现有的，已在跑
   C) 直连 LLM API —— 独立部署、无依赖
```

**分层的价值**：三层各自可替换。换大脑不动 UI；换 UI 不动引擎；引擎迁语言不动任何上层。

## 5. 三种形态对比

| 维度 | 纯 DSH 预设（原方案） | 纯独立网页 | **混合（推荐）** |
|---|---|---|---|
| UI 体验 | 差（聊天流） | **好** | **好** |
| 多真人联机 | ⛔ 砍掉 | ✅ 天然 | ✅ 天然 |
| AI 玩家质量 | 好（DSH 模型与生态） | 取决于自己接 | **好** |
| 分发 | 重（装插件+审批+重启） | **轻（发网址）** | 轻（网址）+ 可选 DSH 入口 |
| 开发摩擦 | 高（B4） | 低 | 低 |
| 信息隔离 | 有未验证面（B2） | **自己完全掌控** | 自己掌控 |
| 复用存量 | ⛔ 全部重写 | ✅ UI + 引擎 | ✅ UI + 引擎 |
| 与 DSH 生态 | 深度绑定 | ⛔ 脱节 | 可选绑定 |

## 6. 推荐路线（**修正原计划的优先级**）

| 阶段 | 内容 | 成本 | 产出 |
|---|---|---|---|
| **S0** | **先确认存量还能不能跑**：`run-werewolf.ps1` + `ov.conf` 都在，但 `logs/` 是空的 | 半天 | 知道手上到底有什么 |
| **S1** | **给存量加"入口"**：让 DSH 侧边栏能打开这个网页（webserver 路由，或直接 `sidebar_open` 本地文件） | 半天 | **在 DSH 里能玩到网页版** |
| **S2** | **大脑做成可插拔**：定义玩家驱动接口，先接 OpenViking（现状），再实现 DSH 实现 | 1–2 天 | 可切换大脑 |
| **S3** | **引擎 TS 化**（我 `03` 文档那套）+ 单测 + 1000 局模糊测试 | 3 天 | 质量保障 |
| **S4** | 预设降级为**入口**：选「狼人杀」→ 法官 persona → `sidebar_open` 打开房间网页 | 0.5 天 | 仪式感 |
| **S5** | UI 面板（`02` 的 M1 体验优化） | — | 可选 |

### 关键修正

原计划把 **P2 引擎 TS 化**放在第一优先（3 人日、最重）。**现在建议降到最后**：

- 存量 Python 引擎**已经在跑** → 先别重写
- 先花 **1 天**（S0+S1）拿到"在 DSH 里能玩到网页版"的可见成果
- 只有当"需要单测/模糊测试保障"或"要把引擎迁进插件"时，才做 S3

**原方案里真正不能省的是隔离设计**（`03` 的可见性矩阵、`04` 的玩家零工具），**可以缓的是语言与引擎重写。**
