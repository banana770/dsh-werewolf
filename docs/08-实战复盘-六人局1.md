## 一、对局结果（游戏本身是成功的）

| 项 | 内容 |
|---|---|
| 板子 | 6 人局：2 狼人 + 预言家 + 女巫 + 2 平民 |
| 真人 | 3 号 · 预言家 |
| 结果 | **好人阵营胜利** |
| 时长 | 2 天 2 夜，5 个 AI 玩家 |
| 出局顺序 | 3 号（放逐）→ 1 号、4 号（夜间）→ 2 号（放逐） |

完整流程全部走通：发牌 → 第 1 夜 → 警长竞选 → 发言 → 投票放逐 → 遗言 → 第 2 夜 → 第 2 天 → 投票 → 终局 → 全身份公开 → 五人复盘。

**AI 玩家的水平超出预期。** 例证 —— 2 号狼人出局后的遗言：

> 「行，认了。我 2 号是狼，4 号也是我队友，这盘输了。复盘一句：4 号悍跳抢警徽抢得漂亮，
> 第二天白天那一刀却砍了 1 号——该刀 5 号或者干脆票型做局，结果把 3 号的遗言给坐实了。
> 三人生死局我一个人喊话，你俩不信我，正常。好人打得稳，服气。」

发言里术语正确（表水 / 站边 / 警徽流 / 悍跳 / 金水 / 票压 / 倒钩）、有推理链、有攻防，**出戏扫描 0 命中**。

## 二、★ 实测确认：子代理继承父级 agent 预设

这是此前只存在于文档推断、无法证实的一条。日志给了确定答案：

| 会话 | `agentPreset` | 含【上帝铁律】 | 含【[玩家N] 前缀规则】 |
|---|---|---|---|
| 主会话（上帝/Lead） | `werewolf` | ✅ | ✅ |
| 玩家 4560c9bc | **`werewolf`** | ✅ | ✅ |
| 玩家 abd4d4a8 | **`werewolf`** | ✅ | ✅ |
| 玩家 d06239e9 | **`werewolf`** | ✅ | ✅ |
| 玩家 de49ce31 | **`werewolf`** | ✅ | ✅ |
| 玩家 e9789e2a | **`werewolf`** | ✅ | ✅ |

**结论：5 个玩家的系统提示词与上帝一字不差**，全都被告知"你是全知全能的上帝（法官）"。

→ 若没有 persona 开头那条**前缀切换规则**，这局会当场崩坏（五个玩家都以为掌握全局）。
→ 这条规则不是过度设计，**是本设计成立的前提**。

**副作用（待评估）**：每个玩家每轮都要背着 5.8 KB 的完整剧本，token 成本显著。
缓解方向见文末。

> 附带确认：主会话头部记录的 `agentPreset: "standard"` 是建会话时的默认值；
> `seq=3` 有一条 `agent-preset/selected → werewolf`，即用户在空白会话里切换了预设。正常行为。

## 三、发现的问题（按严重度）

### 🔴 P1 · 上帝直接报出未揭晓的底牌

第 19 段（真人被放逐、准备留遗言时）：

> **建议你做的事**：明确把 **4 号、2 号** 点成狼（2 号全程跟 4 号归票、还假装质疑金水含金量，
> 这是狼队标准的「倒钩式掩护」）

**当时真人只知道**：自己是预言家、1 号是金水（自己验的）、4 号跳了预言家（必然是假）。
**他并不知道 2 号是狼** —— 是上帝告诉他的。

同类还有：

- 第 11 段：「**他 100% 是狼**（因为真预言家只能是你）」
- 第 16 段：「**4 号是狼**」「他们站的是**狼警长**」
- 第 22 段（真人出局后）：「危急局面：…今天好人只要票出 2 号，好人直接胜利」

这不只是"替玩家下判断"，而是**上帝知道自己知道，于是把答案说了出来**。

**已修**：新增第十节「严禁教练式输出」段落，点名禁止
「关键提示 / 建议你做的事 / 你手里的事实 / 他 100% 是狼 / 你应该对跳」五类表述，
并写死一句：*你不当军师。让真人自己判断，哪怕他会判断错 —— 判断错也是游戏的一部分。*

> ✅ **用户实测反馈（2026-09-30）：剧透问题已解决** ——「上帝现在不会说那么多剧透」。
> 最早那一版「输出纪律」加固即已生效。**P1 关闭。**

### 🟠 P2 · 竞选发言内容永久丢失

第 9 段：`1 号发言完毕。轮到 4 号：` —— **1 号的竞选发言从头到尾没有出现过**。

对照：白天发言阶段上帝把 5/6/1/2 号的发言**攒到真人回合一次性完整播报**（第 16 段），效果很好。
说明上帝有能力播报，只是在**竞选环节漏掉了**。

**已修**：两处。
1. 第四节的竞选步骤加了显式警告 + 一条完整的竞选播报示例；
2. 第五节明确「**攒批播报是推荐做法**」（这正是真人要的效果），但补上铁律：
   *攒批不等于可以不报，绝不允许"报了过场、内容却永远消失"*。

### 🟡 P3 · 剧本里的 kebab-case bug（我的错）

第 2 段：`名字里的下划线不被允许（框架要求 kebab-case），改用 player-1 … player-6`

我在剧本里写的 `player_1` 是**非法名字**，上帝白跑了一轮才自己纠正。

**已修**：全部改为 `player-1 … player-N`，并在剧本里注明下划线会被拒绝。

### 🟡 P4 · 真人出局后直接给了上帝视角

第 22 段：真人被放逐后，上帝给出「🔭 上帝视角（你是观众了，仅你看）」全身份表。

行为本身可以接受（死后观战是常见设计），但**不该由上帝擅自决定**。

**已修**：改为「真人确定出局之后，先问他一句要不要转观众视角」。

### ⚪ P5 · 夜间行动写进正文（用户在游玩中当场抓到）

第 4 段 / 第 21 段：

> **狼队出刀**：4 号报「刀 5 号」，2 号报「刀 1 号」——**票数 1:1 平票**，按规则取最早提交 → **今晚的目标锁定 5 号**。

一句话同时泄露：谁是狼、夜间行动、结算过程。**用户在这局中直接发现并报告，已修**
（新增第十节「输出纪律」+ 第五节的发言播报规则）。

## 四、下一步的取舍（基于实测数据）

| # | 问题 | 现在的解法 | 是否需要更硬的机制 |
|---|---|---|---|
| P1 报底牌 | 提示词加固（第十节） | ⏳ 看下一局还犯不犯。若仍犯，需把"公开播报"变成工具产出而非自由文本 |
| P2 发言丢失 | 提示词加固（第五/四节） | ⏳ 同上 |
| P3 kebab-case | 已写死正确写法 | ✅ 解决 |
| **玩家背 5.8 KB 剧本** | 未处理 | 🔴 **新增关注点**：5 个玩家 × 每轮 = 显著 token。方案：把规则正文移出 persona、放 skill（按需加载），persona 只留一段最短前缀规则 |
| 工具调用可见 | 已知（截图显示为折叠标记，影响比预想小） | ⏸ 暂不处理 |

> **判断**：P1/P2 都是"提示词约束"能压但压不死的问题。连修两轮后，如果同一类错误仍反复出现，
> 就该上 `docs/03-引擎设计.md` 那套确定性方案了 —— 让"该播报什么"由代码产出，而不是靠模型自觉。
