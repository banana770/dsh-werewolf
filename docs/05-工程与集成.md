# 工程与集成（plugin bundle + preset）

> **本文档修正了原计划的一处根本性错误。**
> 原假设：预设是 `~/.dsh/.agent-presets/<id>/` 目录。
> **实际**（官方文档原文）：*"Nothing reads that directory any more."* 那个目录是 **legacy**。
> 现在的预设是 **bundle 补丁里的一行 `@deepseek-ai/dsh-agent-preset` 声明**。

---

## 1. 正确的技术路径（依据官方 skill）

| 事实 | 来源 |
|---|---|
| 预设 = bundle patch 里的声明行，**注册表不扫描目录、不接受 preset 路径** | `dsh-agent-preset-registry/README.zh.md` |
| legacy 迁移路径：`$DSH_HOME/.agent-presets/<id>/` 的 `preset.yml` + `agent.cordis.yml` → 改写成 bundle 声明 | `editing-cordis-compositions/SKILL.md` |
| 声明行 config：`id`（必填，小写+数字+连字符）、`plugins`（必填）、`name`/`description`/`order`（可选）；Loader 行 id 约定 `preset-<id>` | 同上 |
| 在 **workspace 写 bundle 目录**，用 `plugin_manager` `install_bundle`（target = 绝对目录）安装 | `cordis-plugin-development/SKILL.md` |
| **禁止**手写 profile 的 `package.json` / `cordis.patch.yml`，**禁止**在 profile 目录跑 pnpm | 同上 |
| Host 插件 = 共享服务（工具/提示词注册表、Agent loop、会话、持久化、沙箱、模型路由、**子代理后端**） | `editing-cordis-compositions` |
| Preset 插件 = **作用域内**的工具、persona、提示词段落、策略 | 同上 |
| 安装会**在 Host 进程执行插件代码** → 需要 Full access 或审批 | 同上 |
| 替换**已安装**的包需要重启才能加载新 JS 代际；新增 bundle 可经 HMR 生效 | `host-plugin.md` |

### 1.1 由此得出的架构决定

```
bundle 包 @local/dsh-werewolf
  └─ cordis.patch.yml
       └─ insert: preset-werewolf 声明行
            └─ config.plugins: [ persona(法官), werewolf(引擎工具), …按需裁剪 ]
```

**引擎插件挂在预设的 `plugins` 里**（不是挂在 Host 顶层）—— 这样它的工具**只对选了「狼人杀」预设的会话可见**，不会污染普通编码会话。它仍能消费 Host 服务（`ctx.get('subagents')` 等），因为插件注册继承 preset scope。

**游戏状态存哪**：存在插件闭包里的 `Map<gameId, GameState>`。
- 优点：零 realm 麻烦、零序列化、单进程内最简单
- 代价：进程重启丢局（可接受；战报已落盘）
- 若将来要跨会话共享（M4 多人联机）再升级为 `ctx.provide` 服务 + `isolate` 域

## 2. 目录结构（最终形态）

```
D:\dsh工作区\dsh工作区3\dsh-werewolf\
├── package.json              ← bundle 清单（dsh.bundle.patch）
├── cordis.patch.yml          ← ★ 预设声明 + 插件行
├── icon.svg                  ← 插件卡片图标（≤256 KiB）
├── locale/zh.json            ← 显示名与描述
├── lib/                      ← 构建产物（install_bundle 读这个）
│   └── index.js
├── src/
│   ├── engine/               ← 纯逻辑（见 03）
│   └── host/
│       ├── index.ts          ← 插件入口（apply / inject / Config）
│       ├── tools/            ← 暴露给法官的工具
│       ├── judge/            ← 法官主循环（编排玩家）
│       └── prompts/          ← 角色/法官提示词
├── docs/                     ← 本套文档
├── test/                     ← 单测 + 模糊测试 + 端到端
└── scripts/build.sh          ← tsc → lib/
```

**注意**：`install_bundle` 读的是 manifest 里 `exports` 指向的**构建产物**。所以要么先构建出 `lib/`，要么开发期直接写纯 ESM 的 `index.js`（零构建）。`host-plugin.md` 明说："A Host-only bundle needs **no dependencies, install scripts, or build tool**"。

> **决策**：引擎用 TypeScript 写（需要类型安全与单测），但**构建产物必须先进 `lib/`** 再 install。开发期用 `dev_inject_plugin` 热迭代，交付期用 `install_bundle`。

### 3.3 `lib/index.js`（插件入口骨架）

```js
import { defineTool } from '@deepseek-ai/dsh-tools'
import z from 'schemastery'

export const name = '@local/dsh-werewolf'
export const inject = ['tools']

export const Config = z.object({
  maxAiPlayers: z.natural().default(12),
  defaultBoard: z.string().default('standard-9'),
  speechMaxChars: z.natural().default(300),
  actionTimeoutMs: z.natural().default(120000),
})

export function apply(ctx, config) {
  const games = new Map()          // gameId -> GameState（闭包状态）

  ctx.effect(() => ctx.tools.register(defineTool({
    name: 'wolf_board_list',
    description: '列出可用的狼人杀板子（人数与角色配置）',
    parameters: {},
    output: { schema: { type: 'string' }, render: (_a, v) => [{ type: 'text', text: String(v) }] },
    async execute() { return renderBoards() },
  })), 'werewolf: board_list')

  // …其余工具同构（见第 4 节）
}
```

**要点**（来自 `host-plugin.md`）：
- 二选一的导出形态，不要混用：`apply(ctx, config)` + 可选 `inject` / `Config`；**或** service class 作 default export
- 每个资源都用 `ctx.effect(...)` / `ctx.on(...)` 注册并返回清理函数
- 声明了 `Config` 就会在激活时校验该行的 `config`

## 4. 工具清单（暴露给法官会话）

设计原则：**工具只给法官**；玩家只回文本（见 `04` 第 1.1 节）。

| 工具 | 入参 | 返回 | 用途 |
|---|---|---|---|
| `wolf_board_list` | — | 板子表 | 开局询问前展示选项 |
| `wolf_new_game` | `board`, `mode`, `humanSeat?`, `seed?` | `gameId` + 座位表 + （M1）你的身份 | 开新局 |
| `wolf_status` | `gameId` | 阶段 / 第几天 / 存活 / 票型概览 | 法官掌握全局 |
| `wolf_view` | `gameId`, `as: number \| 'god'` | **该视角**的信息快照 | ★ 构造玩家提示词的唯一来源 |
| `wolf_pending` | `gameId` | 当前等哪些座位交什么动作 | 法官据此唤醒玩家 |
| `wolf_act` | `gameId`, `seat`, `kind`, `target`, `expectedStep` | 结果 / `EngineError` | 法官代玩家提交动作 |
| `wolf_speak` | `gameId`, `seat`, `text` | 记录确认 | 记录发言（引擎不校验内容） |
| `wolf_advance` | `gameId` | 新阶段 + 公告文案 | 推进并生成播报 |
| `wolf_default_action` | `gameId`, `seat` | 兜底动作结果 | 超时兜底 |
| `wolf_report` | `gameId`, `style`, `seat?` | markdown 战报 | 复盘导出 |
| `wolf_replay` | `gameId` | `{seed, actions}` | 精确重放 |
| `wolf_rules` | `gameId` | 当前裁决矩阵取值 | 透明化规则开关 |

**`EngineError` 必须作为工具的结构化返回值**（而不是抛异常炸掉会话），让法官能读懂并重试或兜底。

## 5. 法官主循环（`src/host/judge/`）

法官 = 选了本预设的**会话 agent**（不是代码）。它用**已有工具**驱动玩家：

```
1. wolf_new_game(board, mode)          ← 开局
2. loop:
   a. pending = wolf_pending(gameId)
   b. 若 pending 需要某座位决策：
        · 该座位是 AI → spawn_teammate / send_message（首次建，之后复用）
                       消息体 = wolf_view(gameId, seat) + 本轮任务说明
        · 该座位是真人 → ask_user_question（结构化选项）+ 让真人自由发言
   c. 收到回复 → 解析 ```wolf 块 → wolf_act(gameId, seat, …)
   d. 全部提交完 → wolf_advance(gameId) → 得到公告 → 播报
   e. 若 isOver → wolf_report → 结束
```

**这一层用提示词约束**（放在 persona + 一个 `skill` 里），因为它是编排而非计算。确定性靠**引擎工具**保证：法官就算顺序搞错，`expectedStep` 也会拒绝。

**为什么不让代码自驱（路线 B）**：先用现成工具把玩法跑通（路线 A），成本最低、依赖最少。等玩法稳定了，再把 `a–d` 下沉成 `wolf_auto` 工具（路线 C）。

## 6. 安装与验证

### 6.1 安装（交付路径）

```
plugin_manager { action: "install_bundle", target: "D:\\dsh工作区\\dsh工作区3\\dsh-werewolf" }
```

它会自己完成包安装与 bundle 选择。**不要**用 shell 复现这些步骤。

### 6.2 验证（官方指定顺序）

| 步骤 | 命令 | 期望 |
|---|---|---|
| 1 | `plugin_manager { action: "list_bundles" }` | 出现 `@local/dsh-werewolf` |
| 2 | `plugin_manager { action: "list_plugins" }` | 出现 `preset-werewolf` 行，状态 `active` |
| 3 | `cordis_inspect_query`（`Config.listConfigs`，filter name） | 能查到本插件条目与 `packageDir` |
| 4 | `cordis_inspect_query`（`Tool`） | 新会话里能看到 `wolf_*` 工具 |
| 5 | 新建会话选「狼人杀」预设 | persona 是法官，工具面是狼人杀工具 |

> ⚠️ 官方警告：**"Do not infer updated browser code from an unchanged slot id"**、**"restart-required means the change is not live"**。替换已安装包必须重启。

### 6.3 开发期迭代（快路径）

| 阶段 | 手段 | 生效 |
|---|---|---|
| 引擎单测 | `node --test` / vitest，**纯本地，不装插件** | 即时 |
| 插件热迭代 | `dev_inject_plugin` → `dev_reload_package` | 免重启 |
| 预设迭代 | 改 patch → 重新 `install_bundle` | 新会话生效 |
| 交付验收 | `install_bundle` + 重启 + 新建会话 | 权威 |

`dsh-super-injector` 的 `dev_*` 工具链在本机已就绪（`dev_plugin_status` 显示 448 次成功注入），是开发期主力。
